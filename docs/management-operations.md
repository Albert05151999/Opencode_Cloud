# 管理与运维使用说明（0.3.0）

最新源码还包含管理 → 压测：现有 Agent、模拟用户、沙箱资源设置、报告及清理；服务器容量每 5 秒更新，超预算或未知状态拒绝启动。详见 [自动压测](load-testing.md)。此功能需要重新构建，不在原 0.3.0 ZIP 内；交付状态见 [项目进度](../项目进度.md)。

服务器与本地 Web 使用同批 0.3.0 包；构建步骤见 [build-from-source.md](build-from-source.md)。旧服务器不支持的页面会显示升级说明。

## Agent 与沙箱

在管理页的 Agents 中创建、复制或编辑 Agent。复制保留模型和资源引用，私有资源另行复制，不复制会话与工作区。归档会等待任务结束、停止沙箱并禁止新生成；勾选“显示已归档 Agent”后可恢复。

永久删除先要求归档，然后显示会话数、文件数、大小和私有资源影响。输入完整 Agent ID 才能提交。预览有效期五分钟，配置或文件改变后必须重新预览。删除失败时保持“删除中”，重新查看影响后可以重试，不允许恢复部分删除的 Agent。其他 Agent、全局资源、共享内容文件以及既有备份不会删除；这不是备份擦除功能。

“沙箱运维”支持用沙箱 ID、容器 ID、Agent ID 或用户名搜索，按状态过滤、分页，并启动、停止和重启。任务会先等待相关 Agent 空闲，最多 120 秒；超时不强制终止聊天。人工停止意图持久化，聊天不会自动唤醒人工停止的沙箱。重启保留会话状态和工作区，不重发模型请求。

自动恢复设置在同页展开。默认连续三次健康检查异常、十五分钟最多三次恢复，退避 30/60/120 秒；恢复器复用健康监测的连续失败计数，不额外等待三次。健康稳定五分钟重置尝试次数。不能确认空闲、人工停止、归档、模型网关或 Docker 不可用时跳过。策略与计数保存在服务器 SQLite 中。

## 模型与 LiteLLM 的映射

模型表单中的三个概念不同：

| 字段 | 示例 | 含义 |
|---|---|---|
| 平台 ID | `team-coder` | Agent 勾选的稳定名称 |
| 上游模型 ID | 填写账户实际可用模型名称 | 厂商 API 接受的名称 |
| 提供商 | `openai-compatible` | 服务器网关调用适配器 |

例如 OpenAI-compatible 模型保存为 `team-coder` 后，LiteLLM 的 `model_name` 为 `team-coder`，`litellm_params.model` 为 `openai/<上游模型 ID>`。Agent 使用 `cloud-model-gateway/team-coder`，真实 API key 仅供网关使用。

完整顺序：选择厂商模板 → 填写两个 ID 与 API key → 测试当前表单 → 保存 → 发布模型网关 → 打开目标 Agent 勾选该模型并设置默认模型 → 发布 Agent。导入或保存新模型都不会自动分配给 Agent。

| 模板 | 适配器 | 端点填写规则 |
|---|---|---|
| OpenAI | openai | 模板默认 API 地址；填写账户可用模型 |
| Anthropic | anthropic | 模板默认 API 地址；填写 Claude 模型 ID |
| Google | google | 模板默认 API 地址；填写 Gemini API 模型 ID |
| DeepSeek | openai-compatible | `https://api.deepseek.com` |
| Qwen 北京 | openai-compatible | `https://dashscope.aliyuncs.com/compatible-mode/v1`；跨地区须修改地址和对应地区凭据 |
| Z.AI Coding | openai-compatible | 使用 Coding 专用端点及对应套餐凭据 |
| MiniMax 中国 | openai-compatible | 中国端点；国际账户需要调整端点 |

地址与套餐应以各模板链接的厂商文档为准。DeepSeek 地址见 [官方文档](https://api-docs.deepseek.com/)，Qwen 地区选择见 [官方端点说明](https://help.aliyun.com/en/model-studio/base-url)。模板声明位于 `app/provider_templates.json`；已有适配器的新兼容厂商只需添加模板，无需修改沙箱逻辑。

“测试当前表单”使用临时 LiteLLM 容器，不保存或发布，不修改运行网关。测试会产生一次很短的真实模型请求，返回凭据、端点、权限、额度或超时分类。现有环境变量模型继续使用原有已部署模型测试入口。

## 统一导入与导出

“导入导出”中可选择 JSON/JSONC、单个 SKILL.md、单 Skill ZIP 或平台资源 JSON。也可填写 Windows 上指定的原生配置文件路径，由本地服务收集模型、MCP 和实际 Skill 文件。仅收集选定配置，不混合其他自动发现配置。引用配置目录外的 Skill 时需要勾选允许读取外部目录。

本地导入解析 env/file 引用和支持的独立模型认证文件；未解析引用、不支持字段和冲突会显示在预览中。原生 JSON 的 `skills.paths` 是目录引用，不是 Skill 内容；直接上传 JSON 时请另外上传 Skill 附件。目录收集不会执行脚本或安装依赖。

预览不修改资源池，有效期十五分钟。勾选项目、选择目标 ID，遇到冲突先改名或明确替换草稿，再确认导入。提交是一个事务，配置同时被其他页面修改时要求重新预览。模型进入全局候选配置，MCP/Skill/Hook 进入全局草稿；发布并分配给 Agent 是后续显式操作。

普通平台导出对结构化凭据脱敏，Skill 文件和 Hook 源码原样保留。加密资源包使用独立口令，可以选择包含凭据；导入前填入口令，再选择文件进行同样的预览流程。缺失或脱敏凭据不会覆盖已有凭据，新建但没有凭据的模型会停用。

平台格式 v2 包含模型、资源草稿、资源历史版本、Agent 草稿及各历史配置模板和文件摘要。固定资源版本各自进入独立全局草稿，避免导入时假冒已经校验发布的版本。导入后打开“发布、分配与待恢复模板”，发布需要的资源，选择模型和资源版本，再恢复为新的 Agent 草稿并显式发布。不能覆盖已有 Agent。

旧环境变量模型在服务器可以读取自身模型网关配置时转换为可管理模型，保留等价端点；不能读取时写入 warnings，恢复模板时可映射到目标已有模型。模型表单中的“其他等价端点”与主端点共用上游模型名、API key 和参数，通过 LiteLLM 进行路由。

原生导出在同一页面的 Agent 行中，包含 opencode.json、AGENTS.md、实际 Skills 与 Hook 文件，路径改为相对路径。它依赖原服务器模型网关；在其他环境使用前必须配置可访问的网关地址及 MCP 凭据。原生 ZIP 可以重新导入模型/MCP/Skills，原生插件入口给出不迁移提示；Hook 完整迁移应使用平台格式。

所有配置包均不含聊天记录、工作区或容器磁盘。标准配置包上限 20 MiB，加密包上限 40 MiB、解密后 20 MiB；本版采用较小的有界请求，未采用规划中的 200 MiB 建议值。不要把配置包当作整个平台备份。

## 运维详情与中断处理

沙箱行中点击“详情”，查看容器运行状态、健康状态、任务状态、CPU/内存、采样时间、所属会话和最近操作。无法采样时显示未知，不把未知当作空闲。

强制操作必须先查看受影响会话并输入完整沙箱 ID。它会中断任务，记录受影响会话，不会自动重发聊天。普通操作仍等待任务排空。任务记录分页展示；排队、校验或等待中的任务可取消，开始应用或永久删除后不可取消。

控制器重启后按持久检查点核对容器状态。已完成启动不会再重启一次；已经停止的安全操作可继续；无法确定操作是否完成时标记失败，要求管理员检查后重试。自动恢复共用此流程，可对单个 Agent 关闭；当前与发布共享串行锁，因此实际恢复并发为 1，不超过设置的上限 2。

## 验证命令

```bash
python -m pytest tests/unit
python scripts/verify-operations-runtime.py
python scripts/verify-management-runtime.py
```

后两个命令要求 Linux、Docker 和已构建的运行镜像。运维脚本不要求模型完成请求；管理脚本要求可用的真实模型网关。脚本只清理自身唯一实例标签下的临时容器。

```powershell
Set-Location web
npm run build
npm test
$env:WEB_TEST_BASE_URL = 'http://127.0.0.1:18766'
npx playwright test
```

浏览器测试使用模拟远端 API，不等同于真实模型和 Docker 验收。
