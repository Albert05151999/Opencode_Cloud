## 部署布局

目标为 x86_64 Linux Docker Engine/runc 单机部署。控制器运行于独立镜像，使用宿主机网络访问 Docker 发布的 loopback 原生端口；Docker socket 仅供受信任的控制器使用。沙箱继续使用独立网络命名空间及既有资源、只读根文件系统和租户挂载约束。

`/srv/cloud-agent` 保存配置、Agent 定义、SQLite、用户 workspace/state；控制器内外保持相同绝对路径，保证通过 Docker API 创建的 bind mount 指向宿主机实际目录。服务停止与卸载默认保留用户持久数据。重装不得覆盖已有自定义配置。

模型网关保留宿主机 loopback 与 Docker bridge 两个绑定，供控制器和隔离沙箱访问。密钥由安装者提供的独立 `.env` 注入，仅进入模型网关。发布 ZIP 只包含 `.env.example`。未实现认证适配器期间，控制器和监控默认监听 loopback；远端访问由部署者提供受信任入口。

Prometheus/Grafana 作为独立服务，与控制器和模型网关一并固定镜像摘要并提供离线镜像。发布脚本读取中央配置的端口生成监控目标，避免开发机隐式依赖。

## 构建资源与可重复验证

镜像串行构建，压缩限制线程与压缩级别，避免自动使用所有核导致宿主机内存压力。冻结依赖表示输入版本及内容受约束；只有另行比较两次构建摘要后，才能声称镜像字节完全可复现。

最终验证使用与开发 Docker daemon 隔离的干净环境，仅复制 ZIP 与外部测试密钥。环境先验证 checksum、加载镜像，再执行 doctor/install/readiness/原生 API/SSE/隔离/文件与真实模型八路突发。任何嵌套容器测试的共享内核边界必须明确记录；不得把它写成独立物理机性能结果。
