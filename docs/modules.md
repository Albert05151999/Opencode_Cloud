# 模块职责与调用关系

本文用于部署、配置和排障。接口地址、Header、Body 与示例见 [API 使用手册](api.md)，安装步骤见 [部署说明](deployment.md)。

## 服务模块

默认离线包包含 8 个镜像；Compose 常驻启动 7 个服务，`agent_runtime` 由沙箱管理按需创建。版本以各目录的 `module.yaml` 为准，整包版本以根目录 `VERSION` 为准。

| 模块 | 具体作用 | 数据或配置 | 如何理解它的耗时 |
| --- | --- | --- | --- |
| `api_gateway` API 网关 | 对外统一入口，校验管理员凭据，将管理、会话、文件、观测请求转给对应服务，透传流式响应和 Trace 上下文。默认对外端口 18080。 | 根 `.env` 的入口端口、管理员令牌；`config/api_gateway`。 | 一次 HTTP 请求从进入到响应结束。创建会话与提交消息是不同请求；异步请求返回 204 不表示 Agent 已执行完毕。 |
| `catalog_service` 配置目录 | 管理全局模型及账户池配置、Agent 草稿和生效版本、MCP/Skill/Hook 资源、示例模板、归档删除和配置导入导出；提供发布所需配置包和调用权限检查。默认端口 8101。 | `data/catalog_service` 中的配置与资源；`config/catalog_service`。 | 配置读取、授权或管理接口耗时，不是模型推理时间。 |
| `sandbox_manager` 沙箱管理 | 根据 Agent 和用户定位或创建沙箱；执行准入、并发控制、CPU/内存配额、工作目录准备、健康检查、空闲回收、停止/重启/销毁；把原生 OpenCode 请求和事件流路由到沙箱，保留会话路由。默认端口 8102。 | `data/sandbox_manager` 的路由、沙箱状态和已发布 Agent 文件；Docker 容器；宿主机工作目录映射。 | 既有路由请求总时长，也有准入、锁等待、读取配置、准备目录和容器就绪等子阶段。事件订阅长连接不等于任务忙碌。 |
| `agent_runtime` Agent 运行时 | 在隔离容器中运行 OpenCode，加载 Agent 指令、模型、MCP、Skills 和 Hooks；完成模型调用、工具执行、多轮推理与最终回复；产生运行时及工具事件。 | 挂载的 Agent 配置、工作目录和 OpenCode 会话数据；容器端口由沙箱管理分配。 | “Agent 整轮执行”从 OpenCode 用户消息创建到最终助手消息完成，包含模型等待和工具执行。不是某一个串行步骤，也不是浏览器端到端耗时。 |
| `model_gateway` 模型网关 | 提供 OpenAI 兼容模型接口，使用 LiteLLM 将全局模型名称映射到供应商模型和账户部署，使用已发布账户池进行路由；透传生成结果并记录模型调用计时。默认端口 8104。 | `data/model_gateway` 的生效模型配置；供应商 Key 来自安装配置或管理端发布，不能放到客户端。 | HTTP 跨度是模型请求全程，包含上游等待、生成、网络和转发。子阶段区分本地准备、SDK 等待、首片段等待与后续流；没有直接测量供应商内部纯计算时间。 |
| `file_service` 文件服务 | 分配或复用用户/会话工作目录，提供文件列表、上传、下载和管理，协调工作区使用与清理。默认端口 8103。 | `data/workspaces` 与文件服务状态；工作目录映射到沙箱。 | 目录准备、文件传输或文件管理操作耗时。删除沙箱容器不等于删除映射文件。 |
| `operations` 运维服务 | 执行发布、升级等管理任务及恢复流程，保存任务记录，协调服务准入，提供资源容量、压测执行与测试清理。默认端口 8105。 | `data/operations` 的任务、压测与恢复状态；`config/operations`。 | 运维接口或任务阶段耗时。实际 CPU 使用率和已分配 CPU/内存配额是不同指标，不能互相替代。 |
| `observability` 观测服务 | 读取各服务结构化日志，按模块、Trace ID、Session ID 检索和下载；聚合父子跨度、会话时间线和模块覆盖时长；按保留规则清理日志。默认端口 8106。 | 共享 `log` 目录；`config/observability` 的保留和扫描限制。 | 展示已有记录，不会把缺失数据补成 0。模块覆盖时长对同模块重叠区间去重，但包含下游等待，因此不能跨模块相加。 |

内部端口用于服务间通信，应通过 API 网关访问公开接口；不要把内部服务令牌当成管理员凭据。

## 本地 Web 与辅助目录

| 模块或目录 | 作用 |
| --- | --- |
| `admin_web` | 本机运行的管理和聊天界面及本地代理，默认 `127.0.0.1:18765`。连接远程 API 网关，配置模型、Agent、资源，查看发布、沙箱、日志和调用链。独立构建，服务器离线包不包含它。 |
| `shared_libs` | 各服务共同使用的配置类型、认证、HTTP/追踪、日志、指标和基础工具；不是独立服务。 |
| `config` | 各模块默认配置、环境覆盖、配置校验与渲染工具、初始化种子和安装检查。根 `.env` 决定安装预配置；后续页面配置保存在服务数据中。 |
| `build_image` | 根据源码和锁定依赖构建镜像，生成 Compose、安装脚本、配置、校验清单和离线归档。 |
| `contracts` | 对外路由和模块接口约束，是实现、测试和接口文档校验的依据。 |
| `test` | 单元、服务集成、契约、构建及浏览器回归测试。 |
| 可选 `nginx` | 域名模式的反向代理入口，处理 HTTP/HTTPS 转发；默认 IP 模式不启动。 |

## 一轮会话如何经过这些模块

1. 本地 Web 经 API 网关创建会话。沙箱管理检查权限和准入，读取已发布 Agent 配置，准备文件工作区，复用或启动 OpenCode 容器。
2. Web 提交用户消息。异步接口只确认接收，后续回复经事件订阅送到页面。
3. OpenCode 开始执行，调用模型网关；网关根据全局模型配置选择上游模型账户。
4. 模型要求调用工具时，OpenCode 执行工具，并可能再次调用模型。多个模型调用不一定串行，应以实际起止时间为准。
5. 最终助手消息完成，记录 Agent 整轮耗时。观测服务将同一 Trace/Session 的记录聚合供查询。

运行时、API 请求和模型请求属于不同层级，父调用等待子调用时横条会重叠。瀑布图中的服务名表示记录来源，动作和请求路径说明本次调用的作用。
