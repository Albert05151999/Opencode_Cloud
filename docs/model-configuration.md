# 模型与 Agent 配置

**全局模型名**供 Agent 选择；**账户配置**决定请求哪个供应商、哪个上游模型以及使用哪个 Key。

## 去哪里修改

| 需求 | 修改位置 |
| --- | --- |
| 新安装自带模型和 Agent | 根 .env，重新构建发布包 |
| 已安装平台修改模型、Key、账户池 | Web → 模型配置 → 编辑 → 保存 → 发布模型网关 |
| 修改 Agent 模型、指令和资源 | Web → Agent → 编辑 → 保存 → 发布 |
| 查看生成的 LiteLLM 映射 | 模型编辑器和全局配置预览 |
| 查看公开示例 | config/catalog_service/seeds/models.minimax-glm.json |
| 迁移配置 | [导入导出](import-export.md) |

已安装平台以 Catalog 保存的配置为准。修改源码示例 JSON 不会自动修改正在运行的平台。

## 两个模型和多个账户

| 全局别名 | 上游配置 | 默认预设 Agent |
| --- | --- | --- |
| glm | ZAI_BASE_URL、ZAI_MODEL、智普账户池 | Code |
| minimax | MINIMAX_BASE_URL、MINIMAX_MODEL、MiniMax 账户池 | Data |

`glm` 有两个账户时，LiteLLM 会生成两个同名 `model_name: glm` 的部署，各用自己的 Key。Agent 仍只选择 `glm`。Router 在可用部署之间分配请求，账户可设置独立 RPM、TPM、权重及上游地址、模型覆盖值。同一 Key 重复填写不会增加独立配额。

## 用 .env 预配置

```dotenv
MINIMAX_API_KEY=你的Key
MINIMAX_API_KEY_2=
ZAI_API_KEY=你的Key
ZAI_API_KEY_2=
PRESET_AGENTS=code:glm,data:minimax
```

- 没有供应商 Key：不创建模型，仅默认 URL、模型名非空不会生成占位记录。
- 第二个 Key 非空：加入同一模型账户池。
- PRESET_AGENTS 为空：没有预设 Agent，即使已配置模型。
- Agent 指向未配置模型：构建报错。
- .env 不存在或预设项为空：部署可登录管理的空平台。

执行 `python3 build_image/build.py bundle` 即可，安装负责真实导入和发布。`code:glm` 创建 `agent-code` 并选择 glm；`data:minimax` 同理。凭据进入私有运行配置，不写入镜像层。

复杂账户池、自定义 Agent 和资源绑定先在页面配置，再导出包，用 .env 的 `BOOTSTRAP_BUNDLE` 初始化下一次部署。

## 在页面从零配置

1. 模型配置点击“使用 MiniMax 示例”或“使用 GLM 示例”。示例只填表，不自动产生记录。
2. 核对上游地址、模型名和套餐，填写 Key，测试账户。
3. 多账户需求添加账户并逐个测试。
4. 保存，再发布模型网关；保存草稿不表示运行配置已更新。
5. 创建 Agent，选允许模型和默认模型，填写指令，启用并发布。
6. 发布成功后创建会话，验证回复与工具调用。

页面等待发布任务结果，失败原因显示在当前操作处。“已提交”“处理中”不等于成功。修改上游映射需发布模型网关；修改 Agent 模型选择或资源版本还需发布 Agent。

## 每个 Agent 的沙箱 CPU 和内存

进入 **Agents → 编辑 → 沙箱资源**，CPU 可选 1、2、4、8 核，内存可选 1、2、4、8 GiB，两者独立选择。选择“沿用服务器默认值”时使用部署的沙箱默认配置，已有 Agent 保持原有行为。

保存后点击 **发布**，等待“发布成功，配置已生效”。发布会重建该 Agent 的现有沙箱，映射的工作目录保留。限制作用于每个沙箱；同时运行多个用户的沙箱仍需服务器有足够资源。工作目录使用服务器目录映射，不配置容器磁盘容量上限。

导出、复制和模板恢复会保留这些设置；通过 `BOOTSTRAP_BUNDLE` 也可把它们带入新部署。Agent 配置 JSON 的对应字段是 `cpu_limit`（例如 `2`）和 `memory_mb`（例如 `4096`，即 4 GiB），省略或填 `null` 表示继承服务器默认值。

## 粘贴原生 OpenCode JSON

模型编辑器支持原生 JSON、JSONC 和已转义的 JSON 字符串。解析后选择模型、填入表单，检查后保存，无需手工转义整段内容。

粘贴不读取本机 `{env:...}`、`{file:...}`，缺失值会提示补齐。需要收集文件引用时使用导入导出页面的本机配置路径入口。解析成功不等于上游可用，仍需测试账户。

## 常见问题

**没有 Agent：** 空平台或 PRESET_AGENTS 为空时正常，创建 Agent 或从导入导出页的示例模板恢复草稿，再发布。

**发布提示先发布模型：** 先发布模型网关，再重试 Agent。

**导入模型被停用：** 普通导出不带 Key，需补齐；加密凭据包保留账户池。模板仍需映射资源并发布。

**改 .env 后线上没变化：** .env 是新部署的构建输入，已有平台通过管理页面修改。
